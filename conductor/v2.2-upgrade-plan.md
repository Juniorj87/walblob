# WalBlob v2.2 Upgrade Plan — Product Polish & UX Improvements (Refined)

## Objective
Upgrade WalBlob to v2.2 following strict architectural guidelines. Focus on UX improvements, metadata-aware features, and security transparency without refactoring existing logic or deleting components.

## Key Files & Context
- `src/components/sections/Dashboard.tsx`: Main UI.
- `src/components/sections/Retrieve.tsx` / `RecoveryBlock.tsx`: Recovery flow.
- `src/hooks/useWalrus.ts`: Walrus integration.
- `src/utils/metadata.ts`: Metadata protocol (adding SHA-256).
- `src/utils/encryption.ts` / `decryptFile.ts`: Cryptographic operations.
- `index.html`: SEO & Meta tags.

## New Components & Utilities
- `src/context/NetworkContext.tsx`: Manages Mainnet/Testnet endpoints.
- `src/components/ui/CopyButton.tsx`: Unified clipboard utility.
- `src/components/ui/FilePreview.tsx`: Pre-encryption preview with icons.
- `src/components/sections/Explorer.tsx`: Read-only blob availability checker.
- `src/utils/hash.ts`: SHA-256 calculation utility.

## Implementation Steps

### Phase 1: Infrastructure & Shared Components
- **Priority 7: Network Switch (Infrastructure).**
  - Implement `NetworkContext.tsx` to provide `publisherUrl` and `aggregatorUrl`.
  - Wrap the application in `NetworkProvider`.
  - Update `useWalrus.ts` to consume URLs from context instead of env/hardcoded defaults.
- **Priority 4: Copy Button (Standardization).**
  - Create `CopyButton.tsx` with Framer Motion animations and success state.
  - Replace existing inline copy logic in `Dashboard.tsx`.

### Phase 2: Metadata & Integrity (The "Seal" Protocol)
- **Priority 8: Integrity Verification.**
  - Create `src/utils/hash.ts` using `crypto.subtle.digest('SHA-256', data)`.
  - Update `src/utils/encryption.ts` to calculate hash of original file and pass it to metadata.
  - Update `src/utils/metadata.ts` to include the SHA-256 hash in the packed header.
  - Update `src/utils/decryptFile.ts` to calculate hash of decrypted data and compare with metadata hash.
- **Priority 1: File Preview.**
  - Create `FilePreview.tsx` using `lucide-react` for file type icons (PDF, Image, Video, Audio, Archive, Document, Unknown).
  - Integrate into `Dashboard.tsx` after file selection but before the queue.

### Phase 3: Dashboard & UX Polish
- **Priority 2: Storage Duration.**
  - Implement duration selector (14, 30, 90, 180 Days) in `Dashboard.tsx`.
  - Convert days to Walrus epochs internally (30 days ≈ 1 epoch).
- **Priority 5 & 12: Analytics & Security Model.**
  - Implement `UploadAnalyticsCard` showing sizes, time, speed, and network.
  - Implement `SecurityModelSection` with the requested visual flow and 4 points.
- **Priority 9 & 10: Content.**
  - Expand FAQ with security-focused questions.
  - Update Footer with v2.2.0 badge and professional links.

### Phase 4: Recovery & Explorer
- **Priority 3: Recovery Package Import.**
  - Update `RecoveryBlock.tsx` and `Retrieve.tsx` to support both Drag & Drop and a "Select Recovery Package" button.
  - Auto-fill all fields (Blob ID, Key, Metadata) after import.
- **Priority 6: Blob Explorer.**
  - Create `Explorer.tsx` standalone section.
  - Fetch blob availability, size, and status from the aggregator.
  - Show Available, Pending, Not Found, or Error states.

### Phase 5: SEO & Final Audit
- **Priority 11: SEO.**
  - Update `index.html` with OG tags, Twitter cards, and meta description.
  - Ensure favicon and social preview images are referenced.
- **Final Verification.**
  - Run `npm run build`, `npm run lint`, and `npx tsc --noEmit`.

## Implementation Rules
- **No Refactoring:** Keep existing `uploadFlow` and `recoveryFlow` intact.
- **No Deletion:** Do not remove existing components.
- **Additive Approach:** Build new features as separate components.
- **Visual Identity:** Maintain Glassmorphism 3.0 / Premium Dark aesthetic.

- Success logs for build, lint, and type check.
- Updated repository tree.
- List of created/modified files.
